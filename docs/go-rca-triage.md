# G2c — Evidence-linked competing hypothesis triage (preview)

This implementation is an **offline, read-only citation gate**. It does **not** independently establish a root cause, verify an Agent action, authenticate an API source, authorize any write, or declare incident recovery. The PR remains Draft.

## Contract

Use the existing Go evidence sources generated by `collect-changes` and `verify-sli` from **the same relevant incident and time window**. The two Go collectors independently obtain Kubernetes rollout history and Prometheus SLI. Do not combine unrelated CI artifacts and imply a single incident.

`review-rca` accepts an untrusted Agent-proposed list of candidate hypotheses:

| Field | Meaning |
| --- | --- |
| `id`, `kind`, `statement` | Candidate identity and hypothesis; `kind` is `DEPLOYMENT_CAUSAL` or `OTHER_CAUSAL` |
| `claimed_status` | Model-generated status; **ignored as an authority** |
| `supporting_refs` | Cited raw-source content digests using `k8s:<sha256>` or `prom:<sha256>` |
| `contradicting_refs` | Conflicting source references, disjoint from supporting citations |

The gate independently decodes each referenced source's stored exact raw HTTP response, recomputes its SHA-256, rejects missing/duplicate/overlapping citations, verifies JSON shape and source category and returns the following bounded verdicts:

- `CORRELATED_NOT_PROVEN`: the **Deployment causal candidate only** cites both Kubernetes and Prometheus, owned revision time overlaps the incident, the reported SLI is unhealthy, and the windows overlap. This is **not** causal proof.
- `CONTESTED`: the candidate cites opposing evidence. It cannot be promoted.
- `UNVERIFIED`: the requirements for correlation are incomplete, disjoint, absent, or unrelated. This cannot be interpreted as refutation of a different root cause.

The outer status is **always** `HUMAN_REVIEW_REQUIRED`, even if the Agent supplied `claimed_status: SUPPORTED`, `CONFIRMED` or `RECOVERED`. The verifier has no `SUPPORTED`/production-release output path.

A valid SHA-256 detects accidental or uncoordinated changes to raw bytes **but is not a cryptographic origin signature**. A malicious party controlling both bytes and digest can forge both. The checker also does **not** independently recompute summarized SLI status or the change relation from raw source objects. Therefore it is **not** a source-authenticated independent RCA adjudicator, and the G2 independent-verification production gate remains **open**.

## Example with grounded evidence references

Use real JSON files from the *same* Golden Incident; do not use artifacts from separate kind runs as a cross-source causal demonstration.

```bash
CHANGES=/tmp/change-evidence.json
SLI=/tmp/sli-assessment.json
K8S_REF="k8s:$(jq -r '.sources[1].response_sha256' "$CHANGES")"
PROM_REF="prom:$(jq -r '.evidence[0].response_sha256' "$SLI")"

jq -n --arg k "$K8S_REF" --arg p "$PROM_REF" '[
  {
    id: "h-rollout",
    kind: "DEPLOYMENT_CAUSAL",
    statement: "The recent rollout may have caused latency",
    claimed_status: "SUPPORTED",
    supporting_refs: [$k, $p],
    contradicting_refs: []
  },
  {
    id: "h-database",
    kind: "OTHER_CAUSAL",
    statement: "Database saturation may have caused latency",
    supporting_refs: [$p],
    contradicting_refs: []
  }
]' > /tmp/rca-candidates.json

go run ./cmd/sre-agent review-rca \
  --changes "$CHANGES" --sli "$SLI" \
  --candidates /tmp/rca-candidates.json \
  --out /tmp/rca-review.json
```

The result creates a new mode-0600 report, with **no Kubernetes or Prometheus write** and no change to the source reports. A broken source SHA, invalid candidate or repeated citation fails closed as `UNKNOWN` (exit code 3, no report). Exit code 0 means **a triage report was created**, not that an RCA was confirmed. Avoid publishing raw evidence bundles without inspecting potential sensitive Kubernetes metadata and Prometheus labels.

## Required follow-up before a production verifier

1. **Independent replay:** reconstruct change relationship and SLI status from decoded raw bytes (not just hashes), validate all observed timestamps, metric labels, Deployment UID/Generation and sample completeness.
2. **Source authentication:** bind exact queries and sources to a signed or separately trusted Evidence Package, with immutable provenance and redaction.
3. **Counterexamples and RCA Oracle:** inject real faults and competing change/metric/log/event histories, compare against externally provided ground truth, report false-positive and abstention rates.
4. **ACP authority and Temporal recovery:** separate identity/policy and execution from validation. All write paths remain disabled; the old Python four-repository gate is still a documented historical dependency.
